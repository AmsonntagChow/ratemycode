## Routing boundary

```text
As a Staff engineer at real-stakes depth, audit evals/fixtures/insecure-checkout for real-money release.

As a Staff Frontend engineer at launch-gate depth, audit evals/fixtures/frontend-dashboard for public launch.
```

The independent reviewer returned exact settings `staff-engineer` / `real-stakes` / `real-money` and `staff-frontend-engineer` / `launch-gate` / `public-launch`. It also observed that the artifacts, roles, degrees, targets, and rubrics differ, so a cross-role same-rubric score delta would be invalid. Neither prompt requested numeric scoring.

## Browser evidence

The dependency-free fixture was served only on `127.0.0.1` and exercised with Playwright 1.58 against headless Google Chrome `150.0.7871.187`. The in-app browser surface was unavailable, so this explicit fallback and its scope were recorded.

Observed results:

- Search is a `DIV` with no role and `tabIndex=-1`; focusing the text input and pressing Enter left status at `Ready`, so a keyboard user could not begin the critical search journey.
- Submitting `acme`, immediately submitting `beta`, and waiting for both promises ended at `2 results for acme`; the slower earlier response overwrote the latest query.
- At a 320 CSS-pixel viewport, the document and `.shell` were 960 pixels wide, producing horizontal overflow.
- After results rendered, there were zero links, buttons, or link/button roles, so the stated “open the latest matching result” journey had no action.
- The changing status node had neither `aria-live` nor `role=status`, so dynamic results were not exposed as a live announcement contract.
- With reduced motion emulated, the results still used `transition-property: all` and `transition-duration: 0.6s`.

These observations establish Chrome runtime behavior only. They do not prove Safari or Firefox support, screen-reader behavior, field Core Web Vitals, production performance, or real-device touch behavior; those remain unverified in an actual launch review.

## Limitations

- The full `with_skill` versus `without_skill`, two-runs-per-arm matrix in `evals/execution_cases.json` was not executed.
- The browser run used a local static fixture and headless Chrome, not Safari, Firefox, a screen reader, a real touch device, production telemetry, or a deployed artifact.
- No product files were edited, no account or credential was used, and no external request was made.
